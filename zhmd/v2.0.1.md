# v2.0.1 — Model Patch Loader 对 QwenImage 的 ConvRot INT8 支持

本发行说明说明 v2.0.0 引入的 ConvRot INT8 路径现已扩展到**所有**模型补丁类型，修复了将 INT8 **Qwen Image** ControlNet 应用到 **Nunchaku Qwen Image** 基础模型时输出噪声/乱码的问题。

---

## 1. 问题

v2.0.0 中，Model Patch Loader（`ModelPatchLoaderCustom`）通过 `comfy_quant` 元数据检测 ConvRot INT8 检查点，并使用 `mixed_precision_ops` 加载，但**仅限 Z-Image ControlNet 分支**。

加载 INT8 Qwen Image ControlNet（`qwen_image_canny_diffsynth_controlnet_convrot_int8.safetensors`，121 个量化层）时仍走旧分支：

```python
dtype = comfy.utils.weight_dtype(sd)   # 对 INT8 检查点返回 torch.int8！
...
model = QwenImageBlockWiseControlNet(..., dtype=dtype, operations=comfy.ops.manual_cast)
```

原始 INT8 张量随后被作为普通 `Parameter` 接入，导致每个 Linear 都使用乱码权重计算：

- 在惰性初始化（Windows/aimdo）路径下，INT8 权重被原样使用，`F.linear` 产生乱码 — 应用到 Nunchaku Qwen Image 模型时表现为**整图噪声**。
- 在其他路径下，构建时直接崩溃：`RuntimeError: Only Tensors of floating point and complex dtype can require gradients`。

Z-Image INT8 正常；QwenImage INT8 不正常。

## 2. 修复

与 HSWQ 模型补丁加载器一致：将 `comfy_quant` INT8 检测**提升到 `load_model_patch` 顶部**，并应用于**所有**分支：

```python
int8_checkpoint = _has_int8_comfy_quant(sd)

if int8_checkpoint:
    dtype = torch.bfloat16                       # 以浮点构建模块图
    operations = _int8_mixed_precision_ops()     # int8_tensorwise + ConvRot
else:
    operations = comfy.ops.manual_cast           # 原有路径不变
```

现在 `QwenImageBlockWiseControlNet`（以及 `SigLIPMultiFeatProjModel`）在检查点为 INT8 时也会使用 `mixed_precision_ops` 构建。`MixedPrecisionOps.Linear._load_from_state_dict` 会消耗 `<layer>.comfy_quant` / `<layer>.weight_scale`，并为每个量化 Linear 接入 INT8 `QuantizedTensor`（`TensorWiseINT8Layout`，`convrot=True`，`convrot_groupsize=256`），因此：

- 权重在内存（VRAM/内存）中保持 **INT8**；
- 前向走 comfy-kitchen 的 `int8_linear` 内核，带**在线 ConvRot 激活旋转**；
- 噪声消失，结果与 HSWQ 加载器 / BF16 检查点一致。

非 INT8 检查点逐字节保持旧的 `manual_cast` 路径。

## 4. 验证结果（RTX 5060 Ti，16 GB，ComfyUI portable）

1. **INT8 Qwen Image 加载** — 121/121 个 Linear 均接入 `QuantizedTensor`（`torch.int8` 存储，`convrot=True`，groupsize 256）。
2. **真实 VRAM 节省** — 实测权重占用：
   - INT8：**1135.6 MB**
   - 等效 BF16：**2266.8 MB**
   - 节省：**49.9%**；`.to(cuda)` 后 GPU 实际只占用 INT8 大小（与 INT8 比值 1.00，与 BF16 比值 0.50）— 权重在 VRAM 中**未被反量化**。
3. **GPU 前向** — `img_in` / `control_block` 走 INT8 内核路径（通过拦截每个 Linear 前向收到的权重确认：全部为 `QuantizedTensor`），输出有限且形状正确。
4. **回归** — BF16 Qwen Image ControlNet：量化权重为 0（旧路径未受影响）；Z-Image INT8：38/38 量化（与 v2.0.0 一致）。

## 5. 使用方法

与之前相同：

1. 重启 ComfyUI（`custom_nodes` 中的节点文件已更新）。
2. 将 INT8 Qwen Image ControlNet 放入 `model_patches`，并在 **Model Patch Loader** 中选择它（`cpu_offload` 同样可用）。
3. 日志行确认路径：`[ModelPatchLoaderCustom] INT8 ComfyQuant detected ... (weights stay INT8 / ConvRot)`。
4. 照常将 `MODEL_PATCH` 连接到 Qwen Image ControlNet 应用节点。

预期结果：控制行为正确，且 VRAM 约为 BF16 检查点的**一半**。
