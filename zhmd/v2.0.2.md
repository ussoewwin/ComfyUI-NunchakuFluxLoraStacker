# v2.0.2 - CCSR ConvRot INT8 与 TensorRT 加速

本版本为插件内的 CCSR 增加两条**彼此独立**的路径：

- **ConvRot INT8 检查点**：既有的 fp16/PyTorch CCSR 节点（`CCSR_Model_Select` / `DownloadAndLoadCCSRModel`）现在可加载量化的 UNet + ControlNet，权重以 **INT8 驻留 VRAM**（显存占用约为原来的一半）。
- **TensorRT 加速**：新增两个节点（`LoadCCSRModelTensorRT`、`CCSR_Upscale_TRT`），ControlNet+UNet 的 apply-model 在 TensorRT 引擎上运行（约 24 ms/步 vs fp16 约 113 ms/步，约 **4.7 倍**加速）。

另外：CCSR 采样器中的 `steps` 现在表示**实际**扩散步数；README 的节点参考也按用途拆分为 fp16/PyTorch 与 TensorRT 两部分。

---

## 1. 两条路径，完全分开

CCSR 现在以**两套独立的节点**提供 - 两者不应混用：

| 路径 | 加载器 | 放大节点 | 后端 |
|---|---|---|---|
| fp16 / INT8（PyTorch） | `CCSR_Model_Select` / `DownloadAndLoadCCSRModel` | `CCSR_Upscale` | PyTorch（fp16；检查点为量化时走 ConvRot INT8） |
| TensorRT | `LoadCCSRModelTensorRT` | `CCSR_Upscale_TRT` | TensorRT 引擎（fp16 构建）+ fp16 VAE/cond_encoder 辅助权重 |

TRT 节点位于独立的 `TensorRT` 类别下；fp16 加载器与 TRT 加载器不共用任何节点。

## 2. TensorRT 引擎节点

### 2.1 仅引擎加载

`LoadCCSRModelTensorRT` **不需要完整检查点**。它加载：

- **TensorRT 引擎**（`nodes/CCSR/trt_engines/*.rtxplan`）- 由融合的 ControlNet+UNet apply-model（固定 64x64 latent）的 fp32 导出构建，再转换为 fp16 I/O；
- **辅助权重**（`ccsr_trt_aux.safetensors`，与引擎放在一起）- fp16 的 VAE + cond_encoder，即引擎之外仅剩的部分。

引擎下拉框会自动列出 `trt_engines/` 下的所有 `*.rtxplan`；辅助文件自动加载。

### 2.2 为什么是融合引擎

该引擎是整个条件化 apply 路径（ControlNet 条件注入 + UNet 去噪）的单一 ONNX 导出，因此图在 ControlNet 与 UNet 之间不会离开 GPU。实测（RTX 5090，tile 512）：

- fp16 PyTorch 路径：约 **113 ms/步**
- TensorRT 引擎：约 **24 ms/步**
- 加速比：约 **4.7 倍**

过程中修复的缺陷（提交 `faa29bf`、`2d50528`）：
- 引擎改在**当前 CUDA 流**上执行 - 此前使用私有流导致 ComfyUI 图死锁；
- 引擎输出转回**输入 dtype** - 此前因 fp16 I/O 不匹配输出全黑。

### 2.3 步数 / 调度

`CCSR_Upscale_TRT` 保留 CCSR 的质检设计：t_max/t_min 频段（默认 0.67 / 0.33）与「首个 tile 预测 → 重新加噪」的流程均保持不变。采样器现在**加密调度**，使截断后的频段恰好包含 `steps` 个时间步 - 即 `steps` 为**实际**扩散步数（已验证：30 步 → 88 细分 → 频段内实际 30 步）。该行为对两条路径（fp16/INT8 与 TRT）一致。

## 3. fp16 节点的 ConvRot INT8 支持

既有的 fp16 加载器现在接受 **ConvRot INT8** 检查点（`real-world_ccsr_convrot_int8.safetensors`）。

量化布局（实现于 `nodes/CCSR/ccsr_int8.py`）：

| 模块 | 量化方式 | 原因 |
|---|---|---|
| UNet Linear 层 | ConvRot（groupsize 256）、`TensorWiseINT8Layout`、`convrot=True` | 与 HSWQ INT8 内核一致 |
| ControlNet Linear 层 | ConvRot（groupsize 256） | 同上 |
| Conv2d 层（UNet + ControlNet） | 普通 INT8（`QuantConv2d`） | ComfyUI 没有 2D 卷积的 ConvRot 后端 |

INT8 通过 `comfy_quant` 元数据自动识别；图以混合精度算子构建，量化权重以 `QuantizedTensor` 接入，因此权重在 VRAM 中保持 **INT8**：

- fp16 检查点：GPU 上约 2.54 GiB
- ConvRot INT8 检查点：GPU 上约 1.40 GiB（417 个量化张量：UNet 282 层 + ControlNet 135 层）

VAE / cond_encoder 保持 fp16（它们不在量化检查点内）。BF16/fp16 检查点完全走原有路径。

## 5. 使用方法

**TensorRT 路径**

1. 将引擎（`*.rtxplan`）与 `ccsr_trt_aux.safetensors` 放入
   `custom_nodes/ComfyUI-NunchakuFluxLoraStacker/nodes/CCSR/trt_engines/`。
2. 添加 **LoadCCSRModelTensorRT** - 从下拉框选择引擎（辅助权重自动加载），无需检查点输入。
3. 连接到 **CCSR_Upscale_TRT**（tile 512 固定、64x64 latent）并运行。
4. 日志会确认 TRT 路径：`TensorRT` 分发、每步打印 `ms/step`。

**fp16 / INT8 路径（接线不变）**

1. 将 CCSR 检查点（fp16 或 ConvRot INT8）放入 `models/unet/`。
2. `DownloadAndLoadCCSRModel` / `CCSR_Model_Select` 通过 `comfy_quant` 自动识别 INT8 并打印加载的量化方式。
3. 照常连接到 `CCSR_Upscale`。

`steps` 在两条路径上行为一致：你设置的数值就是在 t_max/t_min 频段内实际执行的扩散步数。
