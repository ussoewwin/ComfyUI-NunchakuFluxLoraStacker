# v2.1.4 — CCSR TensorRT 按需自动下载、彻底废除 install.py 与依赖统一

本版本彻底废除了 `install.py`，解决了 Comfy Registry (CNR) 因自动二进制下载与子进程 pip 执行触发的安全标记（Security Flagged）问题，将所有 TensorRT 运行时依赖严格统一至 `requirements.txt`，并重构了 `LoadCCSRModelTensorRT` 节点，使其支持在运行工作流时按需从 Hugging Face 流式下载引擎文件并进行 SHA256 完整性校验。

---

## 1. 核心架构改进

### 1. 彻底废除 `install.py` 并解除安全保留标记
- **解除 CNR 安全标记**: 此前 `install.py` 在自定义节点加载时通过子进程调用 `pip` 并使用 `urllib` 自动拉取大体积二进制文件（~2.7 GB 的 RTX 引擎），触发了 Comfy 官方注册表（CNR）的安全审查保留状态（`NodeVersionStatusFlagged`），导致新版本审核积压。
- **纯净注册集成**: 彻底删除了 `install.py`。插件环境依赖完全回归标准的 `requirements.txt` 管理机制，不再在后台隐式执行安装脚本。

### 2. 统一 TensorRT 运行时依赖至 `requirements.txt`
- 将 CCSR TensorRT 所需的所有运行时依赖完全整合进根目录 [requirements.txt](../requirements.txt):
  - `triton-windows; sys_platform == 'win32'`
  - `triton; sys_platform != 'win32'`
  - `tensorrt-rtx==1.6.1.120`
  - `onnx==1.22.0`
  - `onnxscript==0.7.1`
  - `polygraphy==0.53.4`
- 消除隐式依赖，提供透明、可复现的运行环境。

### 3. CCSR TensorRT 引擎按需自动下载
- **按需延迟拉取**: 在 `nodes/CCSR/nodes.py` 中重构了 `LoadCCSRModelTensorRT` 节点，内置了流式下载函数 `ensure_engine_artifact`。
- **启动零延迟**: 引擎文件（`ccsr_apply_f16io.rtxplan` 约 2.7 GB 与 `ccsr_trt_aux.safetensors` 约 384 MB）不再在 ComfyUI 启动或插件安装时预先下载，仅当用户实际排队执行包含 `LoadCCSRModelTensorRT` 的工作流且本地不存在文件时，才会自动从 Hugging Face（`ussoewwin/CCSR-TensorRT-Engine`）流式下载。
- **SHA256 完整性校验**: 下载完成后自动计算并校验 SHA256 哈希值，防止网络中断或文件损坏。
- **动态引擎下拉项**: 即使本地尚未下载引擎文件，节点的引擎选择下拉框中也会默认展示并提供 `ccsr_apply_f16io.rtxplan`，便于直接搭建与加载工作流。

| 变更项 | v2.1.3 及以前 | v2.1.4 |
|---|---|---|
| **install.py** | 启动时通过子进程调用 pip 与 urllib 下载 | **完全废除并删除** |
| **CNR 安全审查状态** | 因自动执行脚本被标记安全保留 | **完全合规** |
| **TensorRT 运行时栈** | 分散于安装脚本与文档 | **严格整合至 `requirements.txt`** |
| **引擎二进制文件** | 安装时预先下载 | **在 `LoadCCSRModelTensorRT` 运行时按需流式下载** |
| **SHA256 校验** | 无 | **内置自动完整性哈希校验** |
| **说明文档** | 包含 `install.py` 自动安装描述 | **中英文 README 均同步更新** |
