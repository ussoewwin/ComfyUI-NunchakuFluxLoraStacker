# v2.1.5 — 兼容 transformers 5.x 修复 Florence-2 崩溃

本版本修复 Florence-2 节点在新版 transformers 5.x 生成策略校验下的崩溃问题。Florence-2-PromptGen 模型的 `config.json` 携带 `forced_bos_token_id: 0`，而 transformers 5.20+ 不再允许在 `model.config` 上携带生成参数，`generate()` 时会直接抛出 `ValueError: You have modified the pretrained model configuration to control generation`。模型加载器现在会从顶层 config 与语言模型（BART）config 中剥离旧式生成参数，并以正确的 BART 默认值显式写入 `model.generation_config`。

---

## 1. 关键修复

### 1. transformers 5.x 下 Florence-2 的 `ValueError`
- **根本原因**：transformers 5.x（当前 5.20.2）强制要求生成参数（`forced_bos_token_id`、`forced_eos_token_id`、`decoder_start_token_id` 等）必须保存在 `model.generation_config` 上——只要其中任何一个残留在 `model.config` 上，`generate()` 就会抛出 `ValueError: You have modified the pretrained model configuration to control generation`。
- **触发条件**：Florence-2-PromptGen 的 `config.json` 自带 `forced_bos_token_id: 0`，`Florence2Config.from_pretrained()` 会将其原样载入 `model.config`。transformers 更新后，所有 Florence-2 任务（caption、标签生成、OCR 等）都会在 `generate()` 调用处崩溃。

### 2. `load_model()` 中的旧式参数剥离
- 加载器现在遍历 `GenerationConfig._get_default_generation_params()`，在模型构建前把除 `use_cache` 以外的全部旧式生成属性在**顶层 `Florence2Config` 与语言模型（BART）config 两处**显式置为 `None`。
- 随后把这些值以正确的 BART 默认值显式写入 `model.language_model.generation_config`：`decoder_start_token_id=2`、`eos_token_id=2`、`pad_token_id=1`、`forced_bos_token_id=0`、`forced_eos_token_id=2`。
- `forced_bos_token_id=0` 是 BART 生成 caption 的必要条件——由于剥离步骤本身就会把这些属性置为 `None`，默认值通过显式 `None` 检查写入。

---

## 2. 变更总览

| 项目 | v2.1.4 | v2.1.5 |
|---|---|---|
| **transformers 5.x 兼容性** | `generate()` 因旧式 config 参数抛出 `ValueError` | **旧式参数从 config 剥离，改经 `model.generation_config` 生成** |
| **BART 生成默认值** | 从 `config.json` 读取（旧路径） | **显式设置：decoder_start=2 / eos=2 / pad=1 / forced_bos=0 / forced_eos=2** |
| **验证** | 未覆盖 | **已在 transformers 5.20.2 上实测模型加载与 `generate()`** |
| **文档** | - | **双语 changelog 条目更新（EN / 中文）** |
